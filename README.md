# Couchsurfing Host Discovery & Outreach Automation

Веб-приложение для поиска Couchsurfing-хостов в контексте поездки, сбора и проверки информации профиля, подготовки персональных stay-request сообщений и управляемой отправки через Autopilot.

Проект — **модульный монолит в процессе перехода к DDD**. Основные правила и прикладные сценарии постепенно выделяются в `core/`; перенос HTTP-оркестрации, SQL и legacy-фасадов ещё не завершён.

## Что умеет приложение

- Вести поездки и очередь хостов с привязкой к Trip.
- Собирать профильные сведения и сохранять снимки в SQLite.
- Ранжировать очередь по подтверждённым сигналам: verified, свежая активность, известное число reviews, совпадение интересов, русский язык и сигналы имени.
- Составлять исходящие сообщения одним детерминированным генератором и проверять их до отправки.
- Требовать явное утверждение точного текста: разрешение связано с Trip, identity хоста, версией сообщения и SHA-256 его содержимого.
- Исключать отправленные хосты, глобальные активные блокировки и неразрешённые `UNKNOWN_OUTCOME` из dispatch-кандидатов.
- Запускать Autopilot, паузу, продолжение и остановку из веб-интерфейса. Отправщик не предназначен для запуска отдельной CLI-командой.
- Подтверждать результат наблюдаемым состоянием Couchsurfing (`View Stay Request`); один HTTP 2xx не считается доказательством отправки.

## Источники истины

SQLite — каноническое хранилище приложения. Файлы БД и runtime-данные находятся в `output/` и не входят в Git.

| Данные | Каноническое место |
|---|---|
| Trip и состояние карточки в поездке | `core_trips`, `core_hosts` |
| Точное пользовательское разрешение на сообщение | `message_approvals` |
| Попытка отправки и её результат | `sending_attempts` |
| Глобальная защита от повторной и конкурентной отправки | `host_identities`, `host_dispatch_locks` |
| События для аудита и отображения | `sending_history`, `core_audit_logs` |
| Снимки собранных профилей | `core_host_snapshots` |

`requests_queue.json` и другие JSON-артефакты не являются runtime-очередью. На старте production-приложение проверяет существующую схему в read-only режиме; автоматическая миграция production-БД не выполняется.

## Структура

```text
app.py                          FastAPI UI/API и координация приложения
auto_sender.py                  Playwright-адаптер отправки; запускается приложением
core/
  application/                  Прикладные сценарии, включая ApproveFoundHosts
  repositories/                 Доступ к поездочным карточкам и данным очереди
  approval_service.py            Разрешение на конкретную версию сообщения
  dispatch_confirmation.py       Проверка доказательств отправки
  dispatch_identity.py           Identity, глобальные блокировки и recovery
  dispatch_reconciliation.py     Адресная сверка подтверждённых попыток
  host_policy.py                 Проверка допустимости хоста для поездки
  messaging.py                   Генерация и QC исходящего текста
  queue.py                       Чтение очереди, проверка кандидатов и dispatch selection
  queue_ranking.py               Детерминированный порядок очереди
  autopilot.py                   Фиксация подтверждённого результата
scripts/                         Инспекция и миграционные утилиты
tests/                           Изолированные тесты жизненных циклов и инвариантов
archive/legacy_tests/            Исторические тесты, исключённые из обычного discovery
docs/ARCHITECTURE.md             Подробное описание границ и переходных компонентов
```

Корневые совместимые фасады и части `app.py`, `core/queue.py`, схемы SQLite остаются переходными компонентами. DDD-переход не завершён; отдельные сервисы и микросервисы не используются.

## Установка и запуск

Требуется Python 3.10 или новее.

```bash
git clone https://github.com/Zergan84/cs-parsing.git
cd cs-parsing
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m playwright install chromium
```

Укажите путь к уже подготовленной SQLite-БД, если используется не стандартный `output/couchsurfing_platform.db`:

```bash
export CS_DB_PATH="/absolute/path/to/couchsurfing_platform.db"
```

Для отдельного каталога runtime-артефактов можно задать `CS_OUTPUT_DIR`. Новая БД должна содержать требуемую production-схему; приложение не выполняет её миграцию при запуске. Для переноса существующих данных сначала изучите `scripts/migrate_legacy_database.py` и `scripts/verify_migration.py`.

Создайте или обновите локальную сессию Couchsurfing:

```bash
python auth.py
```

Запустите веб-приложение:

```bash
uvicorn app:app --host 127.0.0.1 --port 8000
```

Откройте <http://127.0.0.1:8000>. Сессионные данные хранятся локально в `user_data/` и не коммитятся.

## Работа с очередью и Autopilot

1. Выберите активную поездку.
2. Проверьте профили и подготовленные сообщения.
3. Явно утвердите нужные сообщения. Одного статуса `approved` у хоста недостаточно: проверяется разрешение на точный текущий текст.
4. Настройте лимит и интервал в интерфейсе и нажмите Start Autopilot.
5. Контролируйте статус, счётчик, следующего кандидата и журнал отправок в интерфейсе. Для остановки используйте Stop.

Autopilot берёт кандидатов из SQLite, повторно валидирует approval и использует ranking при реальном выборе. Подтверждённо отправленные и неопределённые попытки не отправляются повторно. `UNKNOWN_OUTCOME` требует отдельной сверки и остаётся заблокированным, пока результат не установлен.

## Генерация сообщений

`core/messaging.py` содержит единую детерминированную генерацию и QC stay-request текста. Сообщение проверяется при подготовке и должно оставаться неизменным после утверждения. Во время отправки текст не перегенерируется. Совместимые интерфейсы `message_generator.py` и `CouchsurfingLLM.generate_request()` делегируют этому генератору. LLM-модули предназначены для других задач приложения, а не для создания альтернативного текста непосредственно перед отправкой.

## Тесты и проверки

Обычный pytest discovery ограничен каталогом `tests/`. Тестовые БД создаются отдельно во временных каталогах; production DB и реальные действия на Couchsurfing тестами не используются.

```bash
python -m pip install pytest
python -m pytest -q
```

Тесты из `archive/legacy_tests/` исключены из стандартного запуска. Их можно запускать отдельно явным путём, если проверяется соответствующая старая функциональность.

Утилиты для отдельной диагностики и проверки миграций:

```bash
python scripts/inspect_databases.py
python scripts/verify_migration.py
```

Подробнее о слоях, состояниях отправки, переходных модулях и ограничениях см. [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Локальные данные и Git

`output/`, SQLite-файлы, browser session, `.env`, логи и временные артефакты исключены через `.gitignore`. Секреты и пользовательские данные нельзя добавлять в коммиты. Для runtime-конфигурации используйте окружение машины; не храните пароли и токены в README или исходниках.
