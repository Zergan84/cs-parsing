# Couchsurfing Outreach Platform: Scraper, Context Assembler & Autopilot

Автоматизированная платформа для интеллектуального поиска хостов на Couchsurfing, глубокого анализа анкет, контекстной генерации персонализированных запросов на проживание и безопасной автономной рассылки с имитацией действий человека.

---

## 📌 Ключевые возможности

* **Изоляция поездок (Trip Context):** Привязка поиска, очереди и переписки к активной поездке (город, даты, логистический контекст).
* **Скрапинг и досье хостов:** Сбор профилей через Playwright и Couchsurfing GraphQL API с автоматической дедупликацией, сохранением снапшотов профилей и классификацией по полу/составу.
* **Context Assembler & Personal Facts:** Связывание проверенных фактов хоста с бэкграундом гостя (режиссура, спорт, языки) без шаблонных клише и выдуманных историй.
* **Строгий контроль качества сообщений (Pre-dispatch QC):**
  * *Минимальный профиль (< 25 слов в био):* строго **30–70 слов**, лаконичное уважительное обращение без фальшивых восторгов.
  * *Обычный профиль (25+ слов в био):* целевой объём **60–90 слов** (допустимо 55–130).
  * *Анти-спам фильтр:* полный запрет роботизированных фраз (*"won't crowd your space"*, *"traveling light with a daypack"*, *"55+ countries"*, *"10+ years on CS"*, выдуманных маршрутов в Томаму и неправдоподобных общих интересов).
* **Надёжный автопилот (Live Dispatcher):**
  * Автоматический выбор Trip Card, заполнение полей даты и текста через Playwright.
  * Плавающий интервал **5–10 минут (Human Jitter)** между отправками для защиты аккаунта от спам-фильтров Couchsurfing.
  * **Правило 3 сбоев:** При троекратной ошибке отправки конкретному кандидату хост сдвигается в самый конец очереди (`priority = -100`), а автопилот продолжает работу со следующим кандидатом.
  * **Авто-перегенерация:** При непрохождении предпроверочного QC текст автоматически перегенерируется под требуемые лимиты перед кликом отправки.
  * Синглтон-контроль процессов (исключение параллельных воркеров и гонок за сессию).
  * Фиксация скриншотов формы `before_send` и `after_send` с верификацией HTTP 200 OK.
* **Единый источник истины (SQLite WAL):** База данных `output/couchsurfing_platform.db` с транзакционным хранением состояний, снимков профилей и аудит-лога событий.

## 🚀 Установка и быстрый запуск

### 1. Подготовка окружения
Требуется **Python 3.10+** (протестировано на Python 3.14).

```bash
# Клонирование репозитория
git clone https://github.com/Zergan84/cs-parsing.git
cd cs-parsing

# Создание и активация виртуального окружения
python3 -m venv .venv
source .venv/bin/activate

# Установка зависимостей
pip install -r requirements.txt
playwright install chromium
```

### 2. Авторизация в Couchsurfing
Для боевой работы требуется активная сессия Couchsurfing:

```bash
python auth.py
```
* Скрипт откроет браузер для входа в ваш аккаунт Couchsurfing.
* После успешной авторизации сессионные cookies сохранятся в локальную директорию `user_data/auth_state.json` (исключена из Git).

### 3. Запуск веб-платформы
```bash
python app.py
```
Откройте в браузере: **`http://localhost:8000`**

## ⚙️ Запуск автопилота через CLI

Автопилот можно запускать как через веб-интерфейс (кнопка «СТАРТ АВТОПИЛОТА»), так и напрямую из командной строки для фоновой работы:

```bash
python -u auto_sender.py \
  --daily-limit 200 \
  --min-interval-minutes 5 \
  --max-interval-minutes 10 \
  --jitter-enabled \
  --trip-id "sapporo-trip-3lhdj8egrk7cinen0zyj7uaacvstp-3LhDj8EgRK7CInEn0zyJ7UaaCvS_tp"
```

### Параметры запуска:
* `--daily-limit N` — максимальный суточный лимит отправок (по умолчанию 200).
* `--min-interval-minutes N` — минимальная пауза между отправками (рекомендуется 5).
* `--max-interval-minutes N` — максимальная пауза между отправками (рекомендуется 10).
* `--jitter-enabled` — включение случайного разброса пауз (Human Jitter).
* `--dry-run` — режим симуляции (заполнение формы без нажатия финальной кнопки Send).
* `--target username` — точечная отправка конкретному хосту.
* `--trip-id ID` — привязка к конкретной поездке.

## 🤖 Модели генерации текста (AI / LLM)

Система поддерживает 3 уровня отказоустойчивости генерации:

1. **Google Gemini Flash (приоритет):** быстрое составление текста через REST API `gemini-2.5-flash` при наличии ключа `GEMINI_API_KEY` в переменных окружения или таблице `app_settings`.
2. **Ollama (локально):** автономная генерация через локальные модели `qwen2.5:7b` или `llama3.2:3b`.
3. **Deterministic Fallback Generator:** мгновенное построение уникальных, заземлённых текстов по правилам ТЗ на базе извлечённых из профиля хуков и фактов Андрея, если внешние LLM недоступны.

## 🔒 Безопасность и сохранность данных

* **Сессионные файлы и пароли:** директории `user_data/`, файлы `.env`, сессии и токены полностью изолированы правилами `.gitignore`.
* **Базы данных:** SQLite файлы (`*.db`, `*.sqlite`, `*.db-wal`) не попадают в систему контроля версий во избежание утечки персональных данных хостов.
* **Защита от дублей:** Трёхуровневая дедупликация (проверка по `core_hosts.state = 'sent'`, локальному журналу `sent_log.json` и экспресс-сверка с открытыми диалогами Couchsurfing перед отправкой).
